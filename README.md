# StudyPilot AI — Smart Study Planner

StudyPilot AI is an end-to-end exam-preparation web application built with **React + Vite** and **Python + FastAPI**.

The timetable is generated by deterministic Python logic, so the core planner still works without any AI API. Gemini is optional and is used only for coaching/quiz generation. Open Library and OpenAlex are used for free learning-resource discovery.

## Features
- JWT register/login
- Subjects, exam dates, target marks, importance
- Topics with difficulty, mastery, estimated minutes
- Smart daily planning based on weakness + urgency + difficulty + importance
- Learn / Revision / Practice session types
- Daily workload limits
- Completed-session preservation when replanning
- Task completion with optional self-test score
- Mastery updates and exam-readiness indicator
- AI teacher coach with non-AI fallback
- Active-recall question generation
- Open Library book search
- OpenAlex academic-resource search
- Responsive polished React UI
- SQLite locally, PostgreSQL in deployment
- Render-compatible FastAPI backend and Vercel-compatible frontend

## Run locally
### 1. Backend
```bash
cd backend
python -m venv .venv
```
Windows PowerShell:
```powershell
.venv\Scripts\Activate.ps1
```
Windows CMD:
```cmd
.venv\Scripts\activate.bat
```
Install and configure:
```bash
pip install -r requirements.txt
```
Copy `.env.example` to `.env`, then run:
```bash
uvicorn app.main:app --reload
```
API: `http://127.0.0.1:8000`
Swagger docs: `http://127.0.0.1:8000/docs`

### 2. Frontend
Open another terminal:
```bash
cd frontend
npm install
```
Copy `.env.example` to `.env.local`, then:
```bash
npm run dev
```
UI: `http://localhost:5173`

## Optional Gemini AI
The planner does **not** require Gemini. To enable enhanced coach/quiz features, add only to the backend `.env`:
```env
GEMINI_API_KEY=your_key_here
GEMINI_MODEL=gemini-3.7-flash
```
Never put the Gemini key in the React frontend.

If the key is missing, quota is exhausted, or a request fails, StudyPilot automatically uses built-in teacher guidance and active-recall prompts.

## Free resource APIs
### Open Library
No key is needed for normal low-volume search. Set a contact email so the app identifies itself:
```env
OPEN_LIBRARY_CONTACT_EMAIL=your_email@example.com
```

### OpenAlex
Basic use can work without a key. A free API key is recommended for a larger free daily budget:
```env
OPENALEX_API_KEY=optional_free_key
```

## Database
### Local
Default:
```env
DATABASE_URL=sqlite:///./studyplanner.db
```

### Deployment
Use PostgreSQL, for example a free Supabase Postgres project:
```env
DATABASE_URL=postgresql://USER:PASSWORD@HOST:PORT/DATABASE?sslmode=require
```
The backend automatically normalizes a normal Postgres URL for psycopg.

## Deploy backend to Render
1. Push this project to GitHub.
2. Create a Render Web Service or use `render.yaml`.
3. Root directory: `backend`
4. Build command: `pip install -r requirements.txt`
5. Start command: `uvicorn app.main:app --host 0.0.0.0 --port $PORT`
6. Add environment variables:
   - `DATABASE_URL`
   - `JWT_SECRET`
   - `FRONTEND_ORIGINS`
   - `GEMINI_API_KEY` (optional)
   - `OPENALEX_API_KEY` (optional)
   - `OPEN_LIBRARY_CONTACT_EMAIL` (recommended)
7. Deploy and copy the backend URL.

Use PostgreSQL for deployed persistence. Do not rely on the local SQLite file on an ephemeral free web service.

## Deploy frontend to Vercel
1. Import the GitHub repository into Vercel.
2. Set Root Directory to `frontend`.
3. Add:
```env
VITE_API_URL=https://YOUR-BACKEND.onrender.com
```
4. Deploy and copy the Vercel URL.
5. Back in Render set:
```env
FRONTEND_ORIGINS=https://YOUR-APP.vercel.app
```
6. Redeploy/restart the backend if needed.

## Demo flow
1. Register.
2. Go to Subjects.
3. Click **Load demo subjects** or enter your own syllabus.
4. Go to Planner.
5. Click **Generate smart plan**.
6. Mark sessions complete.
7. Check readiness on Dashboard.
8. Search resources.
9. Use AI Coach.

## Scheduling logic
For each topic the scheduler scores:
- low mastery / weakness,
- days remaining until exam,
- topic difficulty,
- subject importance,
- remaining estimated workload.

It then schedules only within configured daily capacity and attempts to mix subjects instead of placing the same subject in every consecutive slot.

Completed sessions are preserved when you regenerate the future plan. A subject is never scheduled after its exam date.

## Readiness
The readiness indicator combines:
- weighted topic mastery,
- planned-task completion,
- recent quiz/self-test performance.

It is a study-planning indicator, **not a guaranteed prediction of exam marks**.

## Important pitfalls already handled
- Core timetable does not depend on an LLM.
- AI/free-API outages do not break the planner.
- Secrets remain server-side.
- Deployed database can be persistent PostgreSQL.
- CORS is configurable.
- Passwords are hashed.
- User ownership is checked on subjects/topics/tasks.
- External API calls use timeouts and graceful fallback.
- Past exam dates are rejected.
- Mastery stays within 0–100.
